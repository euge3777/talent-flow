ChatGPT and Claude reach TalentFlow through one MCP server.

MCP (Model Context Protocol) is the open standard both assistants use to call outside tools. TalentFlow publishes 8 scheduling tools; the assistant decides when to call them, and TalentFlow decides what is allowed.

The piecesTop to bottom: where you type, how the message travels, and what runs inside TalentFlow.

The yellow layer is the only part built for AI. Everything under it is the same code the web app uses, so the assistant can never do something the product wouldn't let a person do.

One requestWhat happens when a recruiter types into Claude or ChatGPT.

Solid arrows are requests, dashed arrows are replies. The sun marks the only step a person has to take: nothing is sent until the recruiter says yes.

Step by step
  1. Connect once. In Claude Desktop you add TalentFlow to its config file; Claude then starts node src/mcp-stdio.js on your Mac. For ChatGPT or Claude.ai you add the server's public HTTPS address plus your token as a connector.
  2. Handshake. The assistant sends initialize (TalentFlow records the client's name, e.g. claude-ai, for the audit log) and then tools/list. TalentFlow answers with the 8 tools, their input schemas, safety hints such as readOnlyHint, and usage instructions.
  3. The model chooses. When you type a request, the language model reads the tool descriptions and decides which tool to call and with what arguments. TalentFlow never sees your whole chat, only the tool calls.
  4. TalentFlow checks. Each tools/call carries your token. McpSession turns it into your TalentFlow user and applies the same role rules as the web app.
  5. Preview, then confirm. A write tool called without confirm: true only returns a preview. The assistant shows it to you, and only after you agree does it call again with confirm: true.
  6. Same rules, same record. The Scheduler does the real work and writes to the same database, calendars and outbox as the web app. Every action is logged with the source mcp:<client>.
What travels on the wireJSON-RPC 2.0. Shortened.

The assistant calls a tool:

POST /mcp
Authorization: Bearer tf_riya_…
Mcp-Session-Id: 0be2c184-…

{"jsonrpc":"2.0","id":5,"method":"tools/call","params":{
  "name":"send_scheduling_link",
  "arguments":{"application_id":"app_leo","interview_type":"hr_screen",
               "when":"mornings PT, not Friday"}}}

TalentFlow replies with text for the model and structured data for cards:

{"jsonrpc":"2.0","id":5,"result":{
  "content":[{"type":"text","text":"PREVIEW ONLY — nothing sent. Show this to the user …"}],
  "structuredContent":{"preview":true,"understood":["mornings (08:00–12:00)","not fri"],
                       "slots":[{"start":"2026-11-04T18:00:00.000Z", …}], "email":{…}},
  "isError":false}}
The 8 tools
ToolChanges anything?Used for
list_applicationsNoTurn "Leo" into an application ID
list_interviewsNoFind "my interview with Ben"
get_interview_typesNoDurations and who attends
find_interview_slotsNoFree times, with preferences in plain words
send_scheduling_linkYes, after confirmEmail the candidate a booking link
book_interviewYes, after confirmBook a time already agreed
reschedule_interviewYes, after confirmMove an interview, send new times
cancel_interviewYes, after confirmCancel for everyone
Before production
  1. Replace personal tokens with OAuth 2.1 sign-in through the company's SSO, which is what the MCP spec and both directories expect.
  2. Host the server on a real HTTPS domain instead of a tunnel, and remove the ?token= shortcut.
  3. Add ChatGPT in-chat cards (Apps SDK components) on top of the structuredContent the tools already return.
